# 核心机制：双轨胜利与 Ruin 系统

## 1. 设计目标

在保留传统 MOBA「摧毁敌方基地」胜利条件的前提下，增加一条可选择的并行路径：

**通过战略性、有价值的失败积累 Ruin（崩坏）资源，并在关键节点触发翻转，从而获得胜利。**

两条路径都必须：
- 具备明确的技能与决策表达空间
- 能支撑高水平竞技
- 对观众和职业赛有清晰叙事

## 2. 基础框架

游戏仍是标准 5v5 三路推塔结构。  
经济、经验、兵线、野区、防御塔、大龙/暴君等传统系统全部保留。

新增的核心资源是 **Ruin（崩坏）**。

- 队伍共享一个 Ruin 值（0 起步）
- Ruin 只通过「有价值的失败」获得
- 无价值的死亡几乎不提供 Ruin，甚至会降低个人评分

## 3. Ruin 的获取规则

### 3.1 基本原则

只有当失败产生了**可量化的团队收益**时，才计入 Ruin。

系统需要同时记录：
- 死亡时造成的伤害/控制
- 死亡前后是否成功转化了目标（塔、龙、关键击杀）
- 死亡是否帮助队友获得了明显资源或位置优势

### 3.2 主要获取来源（初版）

| 行为 | 说明 | 大致权重 |
|------|------|----------|
| 高价值交换死亡 | 死亡的同时击杀或重创敌方核心，或帮助队友完成击杀 | 高 |
| 目标转化死亡 | 在死亡过程中成功拿下防御塔、龙、暴君等 | 高 |
| 战略性送塔 | 在特定时间窗口主动放弃外塔，换取兵线、视野或发育时间 | 中高 |
| 英雄献祭技能 | 部分英雄拥有「死亡后留下强力效果」的机制 | 中高 |
| 残血强行换人 | 用自己换掉更重要的敌方单位 | 中 |

**明确不计入或大幅降低的情况：**
- 单纯被单杀且无任何输出/控制
- 无脑冲进敌方人群送死
- 连续低价值死亡

## 4. 双轨胜利路径

### 路径 A：传统统治（Dominion）

- 正常发育、打团、推塔
- 摧毁敌方水晶/Nexus 即获胜
- 这是默认且最直接的路径

### 路径 B：崩坏路径（Collapse Path）

当队伍满足以下条件时，可以主动或自动进入「崩坏协议」：

1. 队伍 Ruin 达到阈值（初版建议 80–120，可调）
2. 处于明显经济或人头劣势（防止领先方滥用）

**触发后效果（初版设想）：**

- 进入「崩坏窗口」（持续一段时间，或直到下一次大型目标刷新）
- 窗口期间，死亡会转化为更强的存活队友增益
- 敌方如果强行推进高地或强夺大龙，会额外喂给触发方大量 Ruin 与属性
- 极端情况下，可设计「反噬」机制：敌方在窗口期推掉水晶时，若触发方 Ruin 显著更高，则敌方基地反而爆炸（需谨慎平衡）

窗口结束后，回归传统胜利条件，但触发方通常已获得巨大后期优势。

## 5. 设计原则与约束

1. **价值优先**：系统必须奖励「死得值」，而不是「死得多」。
2. **可反制**：领先方必须有手段减缓或压制敌方 Ruin 的增长速度。
3. **节奏兼容**：崩坏路径不能鼓励前期彻底躺平，必须有时间与获取上限约束。
4. **清晰反馈**：玩家必须能实时看到「这次死亡贡献了多少 Ruin」「当前距离触发还有多远」。
5. **反摆烂优先**：评分系统必须把「战略牺牲效率」和「无价值送死」明确分开。

## 6. 需要验证的关键问题

- Ruin 获取公式如何量化「价值」才足够公平且难以被钻空子？
- 触发阈值设在什么区间最合适？
- 崩坏窗口的时长与强度如何平衡，才不会变成「触发即胜利」或「触发后依然无力」？
- 领先方的反制手段应该强到什么程度？
- 如何在 UI 上让普通玩家快速理解这套系统？

## 7. 当前版本说明

本文档为第一版核心机制描述，重点在于建立清晰的框架与原则，而非最终数值。  
所有具体数字（阈值、权重、持续时间）均为占位，需要通过原型与测试迭代。

欢迎针对以上任何一点提出具体反驳、补充或替代方案。
