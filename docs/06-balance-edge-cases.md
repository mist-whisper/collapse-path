# 平衡与边界情况

## 1. 文档目的

任何新机制在理想对局中都可能成立，但在实际环境中会面对投机、极端阵容、节奏破坏和玩家对抗性利用。  

本文集中列出目前能预见的主要风险与边界情况，并给出初步的缓解方向。  
目标不是立刻给出完美答案，而是把问题暴露得足够清楚，方便后续针对性讨论和原型验证。

## 2. 核心风险分类

### 2.1 前期躺平与消极运营

**问题描述**  
队伍发现自己不擅长传统对线后，可能选择早期彻底放弃资源，专心「创造死亡」来堆积 Ruin，导致对局前中期观赏性与对抗性大幅下降。

**可能表现**  
- 主动送一塔、放弃野区、避免一切有效对抗
- 用最低成本的方式反复死亡 proccing Ruin

**缓解方向**  
- Ruin 获取设置前期衰减或硬性上限
- 低价值死亡的惩罚在前期更重
- 要求死亡必须伴随一定的目标转化或交换质量，才计入有效 Ruin
- 崩坏路径的触发条件中加入「时间」或「经济差距」门槛，防止过早触发

### 2.2 领先方不知如何应对

**问题描述**  
当落后方开始明显堆积 Ruin 时，领先方可能陷入两难：继续强推可能喂更多 Ruin，放慢节奏又可能让对方触发后获得优势。

**可能表现**  
- 领先方犹豫不决，对局节奏停滞
- 观众与选手都感到「不知道正确策略是什么」

**缓解方向**  
- 提供明确的「反崩坏」装备与英雄手段
- 让领先方通过特定行为（例如安全推塔、控制视野、减少不必要的击杀）来有效降低敌方 Ruin 获取效率
- 在界面上清晰提示「当前敌方 Ruin 增长来源」，帮助决策

### 2.3 触发后强度失控

**问题描述**  
崩坏协议触发后，效果如果过强，会变成「触发即胜利」；如果过弱，则变成「触发了也没用」的鸡肋选择。

**可能表现**  
- 触发后落后方瞬间具备碾压能力
- 或触发后依然毫无还手之力，导致路径失去吸引力

**缓解方向**  
- 崩坏窗口设置明确的持续时间或目标次数限制
- 窗口内的增益采用「转化」而非「无条件变强」的方式
- 保留传统胜利条件作为最终兜底，避免完全翻转后无法结束的情况
- 通过大量测试找到「有机会但不保证」的强度区间

### 2.4 低价值死亡与假摔

**问题描述**  
玩家故意用最低成本的方式死亡来刷 Ruin，或在无意义的情况下送死，污染评分与对局体验。

**缓解方向**  
（详见 `03-ranking-anti-grief.md`）  
核心仍然是：系统必须奖励「平均每次死亡的价值」，而不是死亡次数。连续低价值死亡应受到重罚。

### 2.5 对局时间被显著拉长

**问题描述**  
双方围绕 Ruin 进行拉锯，或触发后进入长时间的谨慎试探，导致平均对局时长明显增加。

**缓解方向**  
- 崩坏窗口本身具备一定的时间压力
- 设置 Ruin 获取的边际递减
- 在设计中保留「传统路径仍然是结束比赛的最快方式」这一基本盘

### 2.6 阵容与版本单一化

**问题描述**  
如果高崩坏亲和英雄或特定出装过强，版本会迅速收敛到「必须抢这些英雄/必须出这些装」。

**缓解方向**  
- 亲和度设计保持梯度，而非极端强弱
- 反崩坏手段必须足够有效且多样化
- 避免把崩坏能力过度集中在少数英雄身上

### 2.7 与现有系统的冲突

需要额外关注的交互：
- **投降系统**：触发崩坏路径后，投降是否应该变得更难？或保持不变？
- **买活/复活**：频繁买活是否会成为崩坏路径的核心技巧？需要评估其对节奏和经济的影响。
- **防御塔金币与兵线**：故意送塔换 Ruin 的行为如何平衡。
- **视野与打野入侵**：崩坏路径是否会鼓励极端的视野放弃或野区放弃。

## 3. 数值与阈值的开放问题

以下关键数值目前均为占位，需要通过原型验证：

- Ruin 触发阈值的具体范围
- 不同行为提供的 Ruin 基础值与衰减曲线
- 崩坏窗口的持续时间
- 权重 a / b 在触发前后的具体切换数值
- 低价值死亡的惩罚强度曲线

这些数值如果偏差较大，会直接导致路径过强、过弱或完全不可用。

## 4. 设计原则（针对平衡）

1. **传统路径必须始终是强选项**  
   崩坏路径是额外选择，而不是更优解。

2. **任何投机行为的收益必须低于其风险与惩罚**  
   系统应让「认真计算价值」远优于「无脑刷死亡」。

3. **反制手段必须可见且可执行**  
   领先方不能陷入「我不知道该怎么办」的无助感。

4. **优先解决会破坏体验的问题**  
   节奏停滞、假摔、触发即胜利等问题的优先级，高于「让机制更有创意」。

## 5. 建议的验证顺序

1. 先验证「价值死亡」的识别准确性（能否稳定区分好坏死亡）
2. 再验证触发前后的强度曲线
3. 然后观察对局时长与节奏变化
4. 最后再处理英雄与装备的具体数值平衡

只有前几项基本成立，后续的英雄设计与精细调优才有意义。

## 6. 总结

崩坏路径目前最大的敌人不是「不够有趣」，而是「在真实对抗环境中容易被投机或导致体验崩溃」。  

本文列出的问题需要在进入可玩原型之前被认真对待。  
欢迎针对任何一个具体风险提出更优的解决思路，或指出尚未被识别的新边界情况。
